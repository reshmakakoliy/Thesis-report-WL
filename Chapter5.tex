\section{Introduction}
\label{sec:5.1}

The work presented in Chapters~3 and~4 covers the core forecasting pipeline: the processed dataset, the station clusters, the CFL-EDLSTM model, the four baselines, and an evaluation across seven forecast horizons. Several parts of the planned research are not yet complete. This chapter sets out what has been done, what remains, how each remaining part will be carried out, and how the work is scheduled. Longer-term directions that go beyond the scope of this thesis are noted at the end. The conclusions drawn from the completed work are given in Chapter~\ref{ch:6}.

\section{Remaining Work}
\label{sec:5.3}

\subsection{SHAP-Based Interpretability Analysis}
\label{sec:5.3.1}

Deep-learning forecasts are often hard to explain, and a forecasting tool for flood preparedness is more useful when users can see what drives its predictions. The planned analysis will apply SHAP to the trained cluster models in order to answer three questions. Which input variables and engineered features contribute most to the forecasts? Does their importance differ from one cluster to another? And does the ranking agree with what is known about the hydrology of each cluster (Section~\ref{sec:4.3})? The per-cluster analysis is also needed to fulfil the commitment made in Chapter~2.

The main practical difficulty is that the models take long input windows (150 time steps) with many features, which makes SHAP computation expensive. We plan to explain a sampled set of test windows, use an explainer suited to recurrent networks, and aggregate contributions over time steps and over groups of related features (for example lagged values, cumulative rainfall, and seasonal encodings). For XGBoost, SHAP values from the tree explainer will give a cross-check on the importance rankings. The output will be a global importance ranking, a ranking per cluster, and, if time allows, a view by forecast horizon.

\subsection{Web-Based Visualization Interface}
\label{sec:5.3.2}

The second remaining part is a web interface that makes the forecasts usable by people who do not run the model. It will show an interactive map of the 25 stations, coloured or grouped by cluster, with current, previous, and predicted water levels for each of the seven forecast horizons, and a time-series view for any selected station. An exploratory dashboard was already used internally to inspect the raw station data, and it will serve as a starting point for the layout.

The work breaks down into four steps: exporting the model's forecasts in a form the interface can read, building a service that supplies them, building the map and station views, and testing the whole system on stored forecasts. The comparison view described in Section~\ref{sec:5.3.3} will be added once the FFWC data are ready. The technology choices will be made at the start of this stage, and the interface will be evaluated for correctness and clarity of presentation, not for operational deployment.

\subsection{Comparison with FFWC}
\label{sec:5.3.3}

The Flood Forecasting and Warning Centre of the Bangladesh Water Development Board issues forecasts for many river stations, and setting our forecasts next to them gives an external point of reference. FFWC is used here as a comparison source and not as validated ground truth. The plan is to identify the stations and dates where FFWC forecasts and observations overlap with our test period, align them to a common time stamp, and compare errors at the horizons for which FFWC forecasts are available. We expect the overlap to be partial. In the earlier attempt to recover missing values from FFWC reports, only a small part of the gaps could be matched to our stations and time stamps (Section~\ref{sec:4.2}), and the matching problem may recur here. If the overlap is too small for a reliable statistical comparison, the results will be presented as a case-based comparison, with this limitation stated openly.

\section{Expected Outcomes and Anticipated Risks}
\label{sec:5.5}

On completion, the thesis should contain an interpretable account of which inputs drive the forecasts, evidence on whether clustering and federation improve accuracy, a comparison with an external operational reference, and a working interface that presents the forecasts. Three risks stand out. The first is computation time: SHAP on long sequences and repeated training runs are both costly on a single GPU, so we will start with sampled windows and a limited number of seeds and extend them if time allows. The second is data availability: the FFWC overlap may be smaller than hoped, in which case the comparison will be reduced in scope. The third is that retraining may change the current results. Keeping the first version as a reference and changing the final chapters only once, after all experiments are done, will limit this risk.

\section{Longer-Term Research Directions}
\label{sec:5.6}

Some directions lie beyond this thesis. The first is to extend the framework to other river basins, since the current dataset covers only the Brahmaputra system. The second is to add forecast-driven inputs, such as numerical rainfall forecasts, which would address the limit that the model sees only past observations. The third is to produce probabilistic forecasts with uncertainty bounds, which are more useful for warning decisions than a single value. The fourth is to test the federated design in a genuinely distributed setting, with data held by separate agencies, instead of clusters simulated within one dataset. Finally, evaluation on historical extreme flood events and a pilot with end users would show how the system performs where it matters most.
